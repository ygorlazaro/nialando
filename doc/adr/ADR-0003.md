# ADR-0003: Godot como camada de apresentação e simulação independente

Data: 2026-10-30
Status: Aceito

## Contexto

O projeto muda de rumo: deixa de ser web (React + API + Postgres) e passa a ser um
**jogo desktop em Godot 4 com C#**, alvo inicial Linux (Zorin/Ubuntu), depois Windows.

Precisamos de:
- Simulação testável sem abrir a engine.
- UI que possa ser construída em código C# (testável, amigável a agentes), com poucas cenas `.tscn`.

## Decisão

- **Domain, Simulation, Application e Cli** são bibliotecas .NET comuns (`net8.0`),
  sem nenhuma referência a Godot.
- **Godot é só a camada de apresentação.** Nós Godot são views finas: não contêm
  regra de jogo, só leem view models e enviam ordens.
- **Fachada `GameSession`** (Application): `NewGame(params)`, `LoadGame`, `SaveGame`,
  `Submit(order)` (valida e devolve erros), `RevokeOrder`, `EndTurn()` e consultas que
  devolvem view models imutáveis. A UI nunca altera o estado diretamente.
- **`EndTurn()`** roda fora da thread principal, com progresso, para a UI não travar.
- UI preferencialmente construída em código C#, com poucas cenas `.tscn` (mantidas em texto no git).
- Classes de script Godot são `partial`.

## Consequências

- Testes .NET podem cobrir 100% da Simulation sem Godot.
- O projeto Godot só referencia Application (e, por ela, o resto).
- `TargetFramework` das bibliotecas = `net8.0` (o que o Godot 4.7.2 instalado suporta).
  Projetos Godot em .NET 8 nãoreferenciam bibliotecas `net10.0`.
